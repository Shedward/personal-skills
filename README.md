# personal-skills

Личные скиллы общего назначения для Claude Code и Codex. Оригиналы хранятся
в `skills/` этого репозитория. Claude подключает их через плагин `my`,
Codex — через симлинки `~/.agents/skills/<name>` на папки в репозитории.

## Установка

```sh
curl -fsSL https://raw.githubusercontent.com/Shedward/personal-skills/main/install.sh | sh
```

По умолчанию скрипт клонирует репо в `~/Projects/personal-skills`, ставит
Claude-плагин и создаёт ссылки для Codex. Для режимов `claude` и `both`
нужны Claude CLI и Python 3.
Другой путь — аргументом:

```sh
curl -fsSL https://raw.githubusercontent.com/Shedward/personal-skills/main/install.sh | sh -s -- ~/code/personal-skills
```

Из существующего клона (путь последним аргументом):

```sh
./install.sh --codex "$PWD"   # только Codex
./install.sh --claude "$PWD"  # только Claude
./install.sh --both "$PWD"    # оба приложения, режим по умолчанию
```

Повторный запуск безопасен: правильные ссылки остаются, недостающие
добавляются. При конфликте имени, чужой или битой ссылке установщик
показывает путь и останавливается до создания ссылок; ничего не перезаписывает.
Остальные скиллы в `~/.agents/skills` не затрагиваются. Для нестандартного
каталога Codex: `PERSONAL_SKILLS_CODEX_DIR=/path/to/skills ./install.sh --codex "$PWD"`.
Каталог должен входить в места обнаружения скиллов вашим Codex.

Если Claude-маркетплейс `personal-skills` уже зарегистрирован на другой путь,
установщик остановится до создания ссылок Codex и изменения регистрации.
Ошибка получения или разбора списка маркетплейсов также останавливает установку.

Оба приложения читают рабочее дерево клона, включая незакоммиченное: Claude —
папку локального маркетплейса (правка действует после `/reload-plugins` или в
новой сессии), Codex — цели симлинков (если изменение не появилось —
перезапустить сессию).

Только на чтение, без клона: `claude plugin marketplace add Shedward/personal-skills`.

## Работа

- Claude: `/my:<name>`, например `/my:todo` и `/my:skills-sync`.
- Codex: `$<name>`, например `$todo` и `$skills-sync`, или выбор через `/skills`.
- `skills-sync` — подтянуть обновления, проверить новые локальные скиллы
  обоих приложений, восстановить недостающие подключения, показать незакоммиченное.
- Новый скилл — папка `skills/<name>/SKILL.md`.
- После добавления скилла повторить `./install.sh --codex "$PWD"`, чтобы
  создать ссылку, или вызвать `skills-sync`.
- Коммит и push — руками.

На одной машине оба приложения используют общие оригиналы. Между машинами
синхронизация идёт через Git: commit/push на одной, `skills-sync` на другой.
Удалённые и переименованные скиллы могут оставить битые ссылки — `skills-sync`
покажет их; автоматического удаления нет.

## Зависимости скиллов

`~/.claude/docs/<project>/` — общее хранилище ADR, CONTEXT.md, карт и личных
задач для обоих приложений. `<project>` — каноничное имя проекта, не имя
рабочей копии. Существующие знания не переносятся и не дублируются в `~/.codex`.

Скиллы содержат нужные им правила хранения и работы. Глобальные инструкции
(`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`) и память приложений остаются
отдельными; установщик их не читает и не копирует. `harvest` предлагает
целевой файл перед записью нового правила.

`critics`, `troubleshoot`, `critics-rewrite` используют сабагентов, если они
доступны. В Codex агенты разделяют файловую систему: для переписывания
нужны отдельные git worktree. Без сабагентов скилл сообщает об ограничении.
Доска `todo` использует Python 3 и Plannotator (устанавливается отдельно).
