# Skills sync

Личные скиллы живут в git-репозитории, в `~/.claude/skills` лежат симлинки
на его папки `skills/<name>` — правка скилла на месте сразу попадает в
рабочую копию репо. Скилл держит три вещи в согласии: remote, рабочую копию
и симлинки.

Репо находится через сам скилл:

```sh
git -C "$(realpath ~/.claude/skills/skills-sync)" rev-parse --show-toplevel
```

## Процесс

1. **Состояние**: `git fetch`, затем `git status -sb` в репо.
2. **Подтянуть**: отстаём от remote и дерево чистое → `git pull --ff-only`.
   Дерево грязное или ветки разошлись → стоп: показать `git status` и
   `git diff --stat`, дальше решает пользователь.
3. **Беспризорные**: настоящие папки (не симлинки) в `~/.claude/skills`:

   ```sh
   find ~/.claude/skills -mindepth 1 -maxdepth 1 -type d ! -name 'plannotator-*' ! -name synced
   ```

   По каждой спросить: личный скилл общего назначения → `mv` в `skills/`
   репо; проектный или чужой → оставить как есть.
4. **Линки**: `./install.sh`. Строка `skip …` = локальная копия расходится с
   репо: показать `diff -r`, спросить, какая версия верная, потом `-f` или
   перенос правок в репо.
5. **Отчёт**: что подтянуто, прилинковано, усыновлено; `git status --short`
   и `git log --oneline @{u}..`; готовые команды commit/push для пользователя.

## Ошибки

- Коммитить, стейджить или пушить самому — нельзя, это делает пользователь.
- `install.sh -f` без показа diff — теряет локальные правки.
- Усыновлять всё подряд: проектные скиллы и чужие (`plannotator-*`,
  `synced`) в личный репо не идут.
- Рабочая конкретика (внутренние имена, хосты) в личном репо — перед
  усыновлением просмотреть скилл и предупредить.
