# Debug tricks

Каталог переиспользуемых приёмов отладки. Каждый трюк — отдельный файл в
`tricks/` с фиксированными секциями: **Когда / Как / Нюансы и грабли /
Вариации / Смежные трюки**. Трюки ссылаются друг на друга по имени файла.

## Индекс

| Трюк | Когда брать |
|---|---|
| [temp-deeplink](tricks/temp-deeplink.md) | Нужно открывать багующий/лабораторный экран сразу, без ручных шагов и UI-тапов (агент не умеет тапать по симулятору надёжно) |
| [lab-screen](tricks/lab-screen.md) | Нужно изолировать компонент от прод-окружения и гонять матрицу его конфигураций |
| [file-log-probes](tricks/file-log-probes.md) | Нужно видеть рантайм-поведение: частоты вызовов, ветки, петли — особенно когда UI фризит и обычные каналы наблюдения умирают |
| [clean-repro-project](tricks/clean-repro-project.md) | Нужно доказать границу бага (наш слой vs framework/OS), собрать минимальный репро для радара или экспериментировать без тяжёлой сборки |
| [simulator-driving](tricks/simulator-driving.md) | Механика вождения симулятора агентом: UDID, install/launch/openurl/screenshot, авторизация, клавиатура, флаки-протокол — общий фундамент остальных трюков |
| [video-frame-forensics](tricks/video-frame-forensics.md) | Есть видео-репро анимационного бага/мерцания/гонки отрисовки — разобрать покадрово через ffmpeg: кто анимирует, кто появляется мгновенно, когда случился рендер |

## Как пользоваться

1. Перед дебаг-сессией пробежать индекс: какие трюки лягут на задачу.
2. Выбранный трюк читать целиком — нюансы и грабли там не декоративные,
   каждая строка оплачена реальной сессией.
3. Трюки сочетаются: типичная связка — temp-deeplink открывает lab-screen,
   внутри стоят file-log-probes, а спорная граница уходит в
   clean-repro-project; механика команд — в simulator-driving.
4. Порядок ступеней изоляции: **сначала наблюдать баг там, где он живёт**
   (пробы на прод-экране), и только потом изолировать (лаба → чистый
   проект). Изоляция без наблюдений теряет ингредиенты.
5. Пробы ставятся ВСЕ РАЗОМ (одна сборка — полная картина), а ингредиенты
   при бисекции убираются ПО ОДНОМУ — это разные фазы, не противоречие.

## Ведение каталога (harvest)

Каталог живёт, только если пополняется:

- **Применил трюк — обнови его**: новый подводный камень, новая вариация,
  уточнение шага — дописать в соответствующую секцию файла трюка сразу по
  горячим следам, в той же сессии.
- **Нашёл новый приём — заведи файл**: `tricks/<verb-or-noun-phrase>.md` с
  теми же пятью секциями + строка в индексе выше.
- Трюк — generic-знание. Проектные детали (пути, схемы URL, имена фабрик)
  помечать префиксом проекта: `(hh: …)`. Скелет приёма должен работать в
  любом проекте.
- Устаревший шаг не стирать молча: заменить и пометить, чем и когда
  («ранее — X, с <дата> — Y»), пока есть шанс встретить старое окружение.
- Никаких нарративов «как мы чинили баг N» — только выжимка приёма.
  Хроника сессии живёт в картах подсистем и лаб-README.
