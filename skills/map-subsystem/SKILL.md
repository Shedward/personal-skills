# Map Subsystem

Канонический владелец формата «карты подсистемы» — переиспользуемого
архитектурного контекста, который переживает границы сессий. Карты читает
`/troubleshoot` (фаза 0) и пополняет его harvest.

## Где живут карты

Вне любого гита, общие для всех рабочих копий. Ключ — **каноничное имя
проекта** (`ios-apps`, `Levitan`), не имя папки рабочей копии:

```
~/.claude/docs/<project>/maps/
├── INDEX.md          # 1 строка на карту: - [имя](файл.md) — о чём; сверено <дата>
└── <subsystem>.md    # levitan-navbar.md, magritte-bottomsheet.md, ...
```

## Формат карты (фиксированные секции)

```markdown
# <Подсистема>

> Сверено: <ветка>@<YYYY-MM-DD>

## Слои и ответственности
Как устроено by design: какие слои, кто за что отвечает, кто кем владеет.

## Ключевые типы
Пути + имена символов (файл и тип/метод). БЕЗ номеров строк — они гниют.

## Инварианты и контракты
Что обязано выполняться между слоями; неочевидные допущения API.

## Грабли и история
Известные проблемы и их корни, со ссылками на задачи (MOB-…) и ADR.

## Открытые вопросы
Непроверенные гипотезы, белые пятна.
```

Правила:
- Карта — **прио́р, а не истина**. Потребитель обязан перепроверить несущие
  утверждения по коду и обновить шапку «Сверено».
- Записывать только то, что не выводится тривиально из кода за минуту:
  распределение ответственностей, инварианты, неочевидные связи, историю.
  Не пересказывать код.
- Номера строк запрещены; ссылаться на символы (`Файл.swift` → `Тип.метод`).
- **Никакого WIP**: в карту попадает только состояние основной ветки
  (develop/main). Ничего из незакрытых задач — ни код веток, ни детали
  решений в работе: они ещё могут поменяться (правило пользователя,
  30.07.2026). Знания WIP-задач живут в памяти/ADR до мержа; после мержа —
  harvest в карту.

## Процесс построения карты

1. **Проверить существующее.** Прочитать `maps/INDEX.md` и карту, если есть —
   тогда режим обновления, а не создания с нуля.
2. **Разведка.** Изучить подсистему: структуру модулей, ключевые типы, потоки
   данных/событий, контракты между слоями. Для больших подсистем — Explore
   /cavecrew-investigator сабагентами по направлениям (структура, потоки,
   точки расширения), синтез в главном треде.
3. **Черновик.** Заполнить секции. Всё, в чём нет уверенности, — честно в
   «Открытые вопросы», не выдавать догадку за факт.
4. **Вопросы пользователю.** Один-два точечных вопроса про то, чего нет в
   коде: границы владения (можно ли патчить/форкать), история («почему так»),
   известные ему грабли.
5. **Запись.** Сохранить карту, обновить `INDEX.md` (создать при отсутствии).

## Обновление карты (harvest из /troubleshoot или вручную)

Не переписывать карту целиком: дописать новые инварианты/грабли/типы в свои
секции, вычеркнуть опровергнутое, перенести подтверждённое из «Открытых
вопросов», обновить «Сверено» и строку в INDEX.md.
