# Skills sync

Личные скиллы — плагин `my` из маркетплейса `personal-skills`, добавленного
из локального клона. Claude Code читает скиллы прямо из рабочей копии, так
что правка скилла на месте — это правка в репо.

Репо: `personal-skills.installLocation` в
`~/.claude/plugins/known_marketplaces.json`. Если путь внутри
`~/.claude/plugins/` — маркетплейс добавлен с remote, плагин лежит копией в
кэше: править негде, обновление — `claude plugin update my@personal-skills`,
на этом стоп.

## Процесс

1. **Состояние**: `git fetch`, затем `git status -sb` в репо.
2. **Подтянуть**: отстаём от remote и дерево чистое → `git pull --ff-only`.
   Дерево грязное или ветки разошлись → стоп: показать `git status` и
   `git diff --stat`, дальше решает пользователь.
3. **Беспризорные**: папки скиллов вне репо:

   ```sh
   find ~/.claude/skills -mindepth 1 -maxdepth 1 -type d ! -name 'plannotator-*' ! -name synced
   ```

   - Имя уже есть в `skills/` репо → `diff -r`. Совпадает — предложить
     удалить локальную копию (иначе скилл задвоен). Расходится — показать
     diff и спросить, какая версия верная.
   - Имени в репо нет → спросить: личный скилл общего назначения → `mv` в
     `skills/` репо; проектный или чужой → оставить как есть.
4. **Отчёт**: что подтянуто и усыновлено; `git status --short` и
   `git log --oneline @{u}..`; готовые команды commit/push для пользователя.
   Были изменения — напомнить про `/reload-plugins`.

## Ошибки

- Коммитить, стейджить или пушить самому — нельзя, это делает пользователь.
- Удалять или перезаписывать локальную копию без показа diff — теряет правки.
- Усыновлять всё подряд: проектные скиллы и чужие (`plannotator-*`,
  `synced`) в личный репо не идут.
- Рабочая конкретика (внутренние имена, хосты) в личном репо — перед
  усыновлением просмотреть скилл и предупредить.
