# Portfolio

Портфель объединяет работу от идеи до поставки. Дочерний тикет задаёт объём отдельной поставляемой части работы и её PR. У каждого уровня могут быть свои локальные карточки `todo`. Префикс тикета сам по себе не определяет принадлежность портфелю. Названия ключей, связи в трекере и порядок сдачи смотри в разделе «Портфели» файла `~/.claude/docs/<проект>/CONTEXT.md`, если он есть. Имя проекта каноническое для всех его рабочих копий.

## Фокус чата

При входе в портфель и для общего обзора используй сборщик ниже. При переходе к MOB другого портфеля определи её родителя по связи включения в Jira. Если действующий снимок уже подтверждает принадлежность, используй его.

- «Уведи на уровень портфеля» — перенеси обсуждаемую карточку в группу текущего портфеля.
- «Перенеси в следующую мобу» — перенеси обсуждаемую карточку в группу следующего тикета. Для обоих переносов передай `todo` ID карточки, назначение и причину из обсуждения. Фокус чата сохраняется. Если работа уже попала в текущий diff, покажи, какой код требует отдельного решения.
- «Берём другую мобу» — переключи фокус этого чата на выбранный тикет. Его группу явно передавай `todo` для новых карточек и доски, в том числе при обсуждении без checkout.
- «Покажи доску» в контексте дочернего тикета — доска `todo` его группы. Если группы ещё нет, сообщи, что у тикета пока нет локальных карточек. В контексте портфеля, при явном запросе портфельной доски или вызове `$portfolio` без аргументов — общий обзор ниже. С дочернего тикета сначала определи портфель по трекеру; если связь неоднозначна, уточни портфель. Просмотр соседнего уровня сохраняет фокус.

«Другую» и «следующую» определи по разговору или согласованному порядку работ. Если назначение всё ещё неясно, спроси «Какую мобу имеешь в виду?» и предложи известные варианты. Номер тикета и порядок строк на доске сами по себе очерёдности не задают.

В новом чате начни с явно названной задачи или ключа ветки текущей рабочей копии. При расхождении укажи текущую ветку до работы с кодом.

## Судьба вопроса

| Решение | Кому принадлежит карточка |
|---|---|
| Разобраться позднее в рамках портфеля | Группе портфеля. Открытый вопрос учитывается при сдаче портфеля. |
| Решить в существующем тикете | Передай карточку его группе. |
| Выделить новый тикет в портфеле | Подготовь черновик по правилам проекта. Карточка остаётся в группе портфеля до появления ключа, затем переносится в группу нового тикета. |
| Вынести за пределы портфеля | Сразу перенеси в локальный беклог. Если внешний тикет уже известен — сразу в его группу. Для работы без ключа запиши в теле следующий шаг по заведению тикета. |
| Отказаться от работы | Закрой через `todo` как `dropped` с причиной. |
| Пришёл ответ или согласование | Запиши ответ и ссылку. Решение о закрытии или передаче остатка прими по разделу «Закрыть» скилла `todo`. |

При разборе локального беклога покажи число открытых карточек, ожидающих заведения в трекере, и дату старейшей. Основание для подсчёта — записанное намерение передать в трекер. После заведения перенеси ту же карточку по ключу; при явном отказе закрой с причиной.

## Снимок и доска

Из рабочей копии вызови `python3 -I <папка скилла>/collect.py <ключ портфеля>`. Строка вывода содержит путь к JSON, источник и время данных Jira. Для ответа выбери нужные поля через `jq`; весь снимок или тела карточек загружай только когда они нужны. Например, `.issues[] | {key, status, open: [.cards[] | select(.status != "done" and .status != "dropped") | .id]}`. Путь к тексту карточки — `tasks_root` плюс её `path`.

Кеш общий для чатов и рабочих копий: `~/.claude/docs/<проект>/portfolios/<ключ>.json`. Свежесть Jira видна в `jira_updated_at` и `jira_stale`. При каждом обращении сборщик перечитывает локальные карточки. Jira MCP вызывается при первом сборе, в новый календарный день или при обнаружении закрытия локальной карточки. При недоступности сервера остаётся последний успешный снимок с отметкой об устаревании. После сбоя обычное чтение повторит попытку через 10 минут; явное обновление доступно сразу. После завершения MOB, слияния её PR, изменения состава портфеля или фразы «обнови портфель» вызови ту же команду с `--refresh`. Для простаивающего портфеля фоновых запросов нет.

Параметры отбора проекта (`child_project` и `jira_url`) берутся из `portfolios/config.json`, если он есть. Если в трекере задачи включены через платформенный тикет, найди его среди прямых включений в `portfolio.other_inclusions` и передай `--via <ключ>` для подтверждённого промежуточного тикета; выбор сохранится для этого портфеля. Для другой рабочей копии при необходимости укажи `--project` или `--tasks`. Холодному сбору нужны `uv` и настроенный HTTP Jira MCP.

Для доски выполни `python3 -I <папка скилла>/board.py <снимок.json> <временная папка>/board.html` из рабочей копии. Если фокус чата задан явно, передай `--current <ключ>`; иначе текущий тикет определяется по ветке.

Готовый HTML открой по разделу «Доска» [скилла todo](../todo/SKILL.md): в Codex Desktop со встроенными комментариями — через `../todo/serve-board` во вкладке чата, в CLI или без такого браузера — через `plannotator annotate`.

Состояние PR бери из Forgejo по правилам проекта. Передай проверенные результаты через `--prs <файл.json>` в формате `{"APP-12": [{"label": "#34 · открыт → PLAN-4", "url": "https://example.org/pulls/34"}]}`. Пустой массив означает подтверждённое отсутствие PR, пропущенный ключ — сведения не проверены. Для проверки готовности учитывай слияние PR, локальные вопросы и этапы сдачи.

В строке портфеля счётчики всех его карточек, при раскрытии — только собственные. Раскрыта текущая MOB в работе. Название тикета открывает кешированное описание Jira, карточка — полный текст локальной задачи и вложения. Комментарий `[n]` относится к уникальному номеру на этой сборке доски, `#general-comment` — ко всему портфелю. В Plannotator для навигации нужен режим Interact (из Annotate — Esc).
