# Codeowner

Владельца ищет `codeowner.sh` рядом с этим файлом. Скрипт без зависимостей,
работает на bash 3.2. Флаги — в `codeowner.sh --help`.

## Шаги

1. **Цель → пути.** Сначала свести вопрос к списку путей от корня репо.
   - Экран или фича: найти исходники (grep по имени экрана,
     accessibility-ключу, строке локализации). Взять файлы экрана и папку
     его модуля.
   - «Кого предупредить»: изменённые файлы —
     `git diff --name-only <база>...HEAD` плюс незакоммиченные
     (`git status --porcelain`). Базу брать у ветки, не предполагать.
2. **Запуск.** Передать пути аргументами или списком через `-` (stdin).
   Скрипт запускать из репозитория, по которому задан вопрос. Каждая
   строка вывода — `путь`, `владельцы`, `комментарий правила`.
3. **Ответ.** Сгруппировать пути по владельцам. Комментарий правила дать
   рядом, если он что-то говорит о зоне ответственности (например, имя
   функциональной области). Пути без владельца (`-`) перечислить отдельно.
   Если у файла экрана и папки модуля разные владельцы, назвать обоих.

Шаг закончен, когда у каждого пути из шага 1 есть владелец или он явно
помечен как бесхозный.

## Как скрипт читает правила

- **Шаблон — регулярка** с полным совпадением по пути от корня (Forgejo).
  Также подходит путь как папка: `путь/` или префикс `путь/…`. Это не
  glob из GitHub: `*.swift` там не сработает.
- **Побеждает последнее совпавшее правило** в файле.
- **Регулярки проверяются как POSIX ERE.** Расширения Go RE2 (`\d`,
  `(?i)`) не поддерживаются, и такое правило молча не совпадёт.
- **Файл правил:** `--file`, иначе `$CODEOWNERS_FILE`, иначе первый файл
  с правилами в корне. Файл-заглушку из одних комментариев скрипт
  пропускает. Если правила лежат в нестандартном месте, передать его
  через `--file`.
- **Владельцы** — все токены `@…` и e-mail в строке правила; всё после
  `#` идёт в комментарий.
