# Skills sync

Оригиналы живут в `personal-skills/skills/`. Claude подключает репо как
локальный маркетплейс с плагином `my`; Codex — отдельными симлинками из
`~/.agents/skills/`. Править оригиналы в репо, не копии в кэшах.

Найти репо: разрешить симлинки пути этого `SKILL.md` и от
`skills/skills-sync/` подняться к корню. Проверить `.git`, `install.sh` и
`skills/skills-sync/SKILL.md`. Если скилл загружен из кэша, проверить
`~/Projects/personal-skills`, затем `personal-skills.installLocation` в
`~/.claude/plugins/known_marketplaces.json`, если файл существует. Каталог
внутри `~/.claude/plugins/` — кэш, не рабочий клон. Клон не найден — спросить
путь; не запускать установщик без пути и не создавать второй клон.

## Процесс

1. **Состояние**: `git fetch`, затем `git status -sb` в репо.
2. **Подтянуть**: отстаём от upstream и дерево чистое → `git pull --ff-only`.
   Дерево грязное или ветки разошлись → стоп: показать `git status` и
   `git diff --stat`, дальше решает пользователь.
   Upstream не настроен — сообщить, продолжить локальную проверку без pull.
3. **Беспризорные**: непосредственные папки с `SKILL.md` в
   `~/.claude/skills`, `~/.agents/skills`, `~/.codex/skills`, если существуют;
   учитывать также `PERSONAL_SKILLS_CODEX_DIR`, если задан.
   Симлинки в этот репо уже подключены — не переносить. Чужие симлинки не
   перемещать, битые показать отдельно. `.system`, `synced`, `plannotator`,
   `plannotator-*` и кэши приложений не усыновлять.

   - Имя уже есть в `skills/` репо → `diff -r`. Совпадает — предложить
     удалить локальную копию (иначе скилл задвоен). Расходится — показать
     diff и спросить, какая версия верная.
   - Имени в репо нет → спросить: личный скилл общего назначения → `mv` в
     `skills/` репо; проектный или чужой → оставить как есть. Одноимённые
     кандидаты из разных каталогов сначала сравнить между собой.
4. **Подключения**: если Codex используется (есть `~/.agents/skills`, задан
   `PERSONAL_SKILLS_CODEX_DIR` или текущая сессия — Codex), выполнить
   `sh <repo>/install.sh --codex <repo>`. Это добавит недостающие ссылки и
   проверит существующие. Конфликты показать; не удалять папки ради установки.
   Ссылки на удалённые/переименованные скиллы показать отдельно и предложить
   убрать после проверки цели. Для Claude при изменениях — `/reload-plugins`
   или новая сессия. Если установлен плагин `my@personal-skills` с отдельной
   кэшированной копией, выполнить `claude plugin update my@personal-skills`
   и проверить, что нужные файлы в установленной копии совпадают с репо.
   Не обещать автоматическое чтение изменений из клона; если CLI не обновил
   копию, сообщить об этом, не править кэш вручную.
5. **Отчёт**: что подтянуто, усыновлено и подключено; `git status --short`;
   при наличии upstream — `git log --oneline @{u}..`; готовые команды
   commit/push для пользователя. Если Codex не увидел обновление — перезапуск.

## Ошибки

- Коммитить, стейджить или пушить самому — нельзя, это делает пользователь.
- Удалять или перезаписывать локальную копию без показа diff — теряет правки.
- Усыновлять всё подряд: проектные скиллы и чужие (`plannotator-*`,
  `synced`) в личный репо не идут.
- Рабочая конкретика (внутренние имена, хосты) в личном репо — перед
  усыновлением просмотреть скилл и предупредить.
- На одной машине общий источник обеспечивают ссылки; между машинами —
  Git. Память приложений этим не синхронизируется.
