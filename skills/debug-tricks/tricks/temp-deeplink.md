# temp-deeplink — временная диплинка на экран

## Когда

- Репро требует многих ручных шагов по UI (логин → таб → список → экран), а
  экран нужно открывать десятки раз за сессию.
- Агент водит симулятор сам: надёжных UI-тапов у него нет (`simctl` не умеет
  tap; AppleScript по окну Simulator хрупок), а `simctl openurl` — есть.
- Нужно параметризовать вход: один и тот же экран в разных конфигурациях.

## Как

1. Найти диплинк-инфраструктуру проекта: как парсятся URL, где
   регистрируются обработчики. (hh: протокол `InternalURLDeeplink` c
   `internalURL(path:query:context:)`, регистрация в
   `ServiceFactory+Routing.swift` приложения; дебажные — под `#if INHOUSE`.)
2. Добавить **временный** кейс в существующий подходящий деиплинк (лучше,
   чем новый тип — не трогает регистрацию) или новый тип рядом с дебажными.
   Пометить комментарием «временный, удалить после <задача>».
3. Параметры класть в path-сегменты, не в query: парсинг тривиален
   (`path[2] == "1"`), и URL легко набирать руками:
   `scheme://lab/<param1>/<param2>`.
4. Навигацию писать через штатный роутер/фабрику экранов проекта —
   диплинк только достраивает маршрут до готового Screen.
5. Открывать: `xcrun simctl openurl <UDID> "scheme://…"`. Приложение должно
   быть уже запущено и авторизовано, если экран за авторизацией —
   авторизация без тапов невозможна, см. предусловие в
   [simulator-driving](simulator-driving.md).

## Нюансы и грабли

- **URL-scheme зависит от издания/таргета** (hh: `hhios` — соискатель,
  `hhempios` — работодатель HH, `jtbempios` — работодатель JTB). Проверять
  `CFBundleURLSchemes` в Info.plist собранного таргета.
- Гварды парсера легко забыть: если существующий деиплинк требует
  `path.count == N`, новый кейс с другим количеством сегментов не пройдёт —
  расширять гвард, не дописывать после него.
- Диплинка — код в ветке: перед PR удалить (это диф, его видно). Рецепт же
  сохранить в карте подсистемы/лаб-README, чтобы восстановить за минуту.
- Если экран фризит сразу после открытия — скриншот может показывать ещё
  СТАРЫЙ экран (транзишн не отрисовался): «ничего не произошло» на скриншоте
  ≠ «диплинка не сработала». Смотреть лог-пробы/RSS процесса.

## Вариации

- **Прод-экран как есть**: диплинка уже существует (`…/vacancy/create`) —
  ничего писать не надо, только найти её формат в UI-тестах или
  `*Deeplink.swift`.
- **Параметризованная лаба**: сегменты кодируют матрицу конфигураций
  (`navbar_lab/<0|1 progress>/<none|small|large|empty>`) — одна диплинка
  покрывает весь план экспериментов без пересборки.
- **Вход в DebugMenu-плейграунд**: диплинка ведёт на экран выбора
  плейграундов, если дальше всё равно нужна ручная настройка.
