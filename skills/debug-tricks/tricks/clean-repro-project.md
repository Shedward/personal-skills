# clean-repro-project — чистый проект для границ бага

## Когда

- Спор «это наш код или баг framework/OS» — нужен вердикт без нашего кода.
- Нужен минимальный репро для радара Apple / issue в зависимость.
- Эксперименты, где тяжёлая сборка основного проекта убивает темп итераций
  (чистый проект собирается секунды).

## Как

1. Скелет: папка с `Sources/App.swift` + `project.pbxproj` из
   [templates/minimal-ios-app.pbxproj](../templates/minimal-ios-app.pbxproj)
   (objectVersion 77, `PBXFileSystemSynchronizedRootGroup` — файлы в
   `Sources/` подхватываются сами, pbxproj больше не трогается). Подставить
   имя и bundle id:
   `sed -i '' 's/__APP_NAME__/MyRepro/g; s/__BUNDLE_ID__/com.debug.MyRepro/g' project.pbxproj`.
2. Сборка/запуск без Xcode и подписи:
   ```bash
   xcodebuild -project X.xcodeproj -target X -configuration Debug \
     -sdk iphonesimulator -arch arm64 CODE_SIGNING_ALLOWED=NO build
   xcrun simctl install <UDID> build/Debug-iphonesimulator/X.app
   xcrun simctl launch <UDID> <bundle-id>
   ```
3. **Сначала — воспроизвести, потом — минимизировать.** Перенести в репро
   ВСЕ подозрительные ингредиенты прод-конфигурации разом (иерархия вью,
   констрейнты, тайминги lifecycle-колбэков, present/push, инвалидации).
   Только когда баг воспроизвёлся — бисекцией убирать по одному ингредиенту
   за прогон, помечая «нужен / не нужен».
4. Итог бисекции — таблица ингредиентов в README проекта + вывод «баг
   наш / баг платформы» с доказательством.

## Нюансы и грабли

- **Отрицательный результат первых версий ничего не доказывает.** «В чистом
  проекте не воспроизводится» чаще значит «не перенесён нужный ингредиент»,
  а не «баг наш». Ингредиентом может быть неочевидная мелочь: вложенный
  сабвью с констрейнтами, `invalidateIntrinsicContentSize()` в
  `didMoveToWindow`, модальный транзишн. Идти от полной копии конфигурации,
  а не от пустого экрана.
- **Проверять, что репро-приложение вообще в нужном режиме**: новые
  OS-фичи могут не включаться в минимальном окружении (без
  `UILaunchScreen_Generation` app работает в letterbox-совместимости; часть
  поведения зависит от scene- vs legacy-жизненного цикла). Скриншот в
  начале — убедиться, что визуально режим тот (например, Liquid
  Glass-капсулы на месте).
- Ингредиенты убирать строго ПО ОДНОМУ и после каждого — полный прогон:
  парные взаимодействия ингредиентов при выбрасывании по два невидимы.
- Финальный прогон делать на закоммиченном состоянии файлов (легко оставить
  проект в «промежуточной» версии последней бисекции).
- В README — команды запуска и матрицу бисекции; проект без истории — сам
  себе документация.
- **Единственный файл с top-level кодом обязан называться `main.swift`**
  (`UIApplicationMain(...)` в `App.swift` — ошибка компиляции). Scene-делегат
  через `configurationForConnecting` заработает только с манифестом сцен:
  добавить в pbxproj `INFOPLIST_KEY_UIApplicationSceneManifest_Generation = YES`,
  иначе legacy-lifecycle и пустое окно.
- **Дамп трейтов приватной иерархии** — таймер раз в 0.5 с обходит
  `subviews` целевого контейнера, пишет `type(of:)`, `traitCollection
  .userInterfaceStyle`, `overrideUserInterfaceStyle` в файл только при
  изменении дампа. Отвечает на вопрос «кто и на каком уровне переопределяет
  трейт» без приватного API. (hh: остров iOS 26 переводит в light/dark
  `_UITabBarPlatterView > SelectedContentView/ContentView/_UITabButton`, сам
  `UITabBar` держит трейт окна.)
- **`tintColor.getRed(...)` в дампе врёт для динамических цветов** — резолв
  идёт по `UITraitCollection.current`, не по трейту вью. Цвет проверять
  скриншотом, лог использовать только для трейтов.
- **Стартовое состояние вместо жеста.** Если поведение переключается только
  пальцем (адаптация острова таббара — программный скролл её не триггерит),
  подобрать начальный контент так, чтобы нужное состояние было с момента
  запуска: остров при старте берёт тему по контенту под баром (белая полоса
  во весь экран → сразу light). Параметры контента — через launch args.

## Вариации

- **Репро для радара**: довести до минимума, комментарии в коде — по
  ингредиентам («без этой строки сходится»), README на английском при
  отправке в Apple.
- **A/B зависимости**: два таргета/бранча против двух версий библиотеки —
  когда подозрение на регрессию зависимости.
- **Валидация фикса в изоляции**: применить обход (кламп, порядок вызовов)
  прямо в репро — быстрое подтверждение, что механизм фикса верный, до
  правки основного проекта.
