# lab-screen — тестовый экран-модуль для компонента

## Когда

- Баг подозревается в компоненте/подсистеме, но воспроизводится на тяжёлом
  прод-экране с сетью, авторизацией и стейтом.
- Нужно прогнать матрицу конфигураций компонента (N состояний × M входов)
  быстро и воспроизводимо.
- Прод-экран нельзя дёргать бесконечно (лимиты API, сайд-эффекты).

## Как

1. Проверить, нет ли готового плейграунда (hh: DebugMenu →
   `Playgrounds/<Component>`; у навбара есть и preview-экран с настройками).
2. Если нет — собрать минимальный модуль по конвенциям проекта: экран,
   который рендерит ровно исследуемый компонент с фиксированным стейтом,
   переданным через параметры (не через UI-настройки: агенту тапать нечем).
3. Вход — через [temp-deeplink](temp-deeplink.md) с параметрами конфигурации
   в path-сегментах.
4. Прогонять матрицу: перезапуск приложения между прогонами (чистое
   состояние), скриншот + метрики на каждую точку (команды — в
   [simulator-driving](simulator-driving.md); там же грабля про скриншот
   замёрзшего экрана и протокол для флаки-багов), лог каждого прогона —
   отдельным файлом-артефактом.
5. Интерактивные события в лабе триггерить из кода, не из UI: фокус поля
   (клавиатура) — `becomeFirstResponder`/`@FocusState` по параметру
   диплинки, скролл — программный `setContentOffset`.

## Нюансы и грабли

- **Лаба не воспроизвела — это данные, а не тупик.** Расхождение лабы и
  прода само по себе диагностично: значит, в проде есть ингредиент, которого
  в лабе нет (тайминги транзишна, порядок монтажа, соседний механизм).
  Искать дельту конфигураций, а не выбрасывать лабу.
- И наоборот: **вывод из лабы не переносить на прод без проверки** — в лабе
  может отсутствовать прод-ингредиент, меняющий поведение (дефолты, окружение,
  жизненный цикл). Формулировать выводы как «в лабе X», пока прод не подтвердил.
- Отрицательный опыт («в лабе эффекта нет») сначала проверять на
  чувствительность прибора: достаёт ли лаба вообще до исследуемого механизма.
- Лаба-код временный: удалить из ветки перед PR, рецепт сохранить в карте
  подсистемы (готовые стейты, сегменты диплинки, что покрывала матрица).

## Вариации

- **Постоянный плейграунд** в DebugMenu — если компонент дизайн-системный и
  лаба пригодится команде: остаётся в проекте насовсем.
- **Временный preview-экран** — скелет из Screen + фиксированный State,
  живёт одну задачу.
- **Лаба на границе слоёв**: экран, который вместо компонента рендерит его
  UIKit-обёртку напрямую — когда подозрение на стык SwiftUI↔UIKit.
