# simulator-driving — вождение симулятора агентом

## Когда

- Любая дебаг-сессия на симуляторе: остальные трюки ссылаются сюда за
  механикой команд.
- Нужно понять, каким симулятором пользоваться и как с ним говорить без
  UI-тапов.

## Как

```bash
# Симуляторы: имя, UDID, состояние (Booted/Shutdown)
xcrun simctl list devices available | grep -A15 "iOS 26"
UDID=…   # дальше везде явный UDID — имена повторяются между версиями iOS

# Что установлено (и авторизовано ли — по bundle id издания)
xcrun simctl listapps $UDID | grep CFBundleIdentifier

# Цикл: установить → запустить → открыть диплинку → скриншот → убить
xcrun simctl install $UDID path/to/App.app     # переустановка НЕ сбрасывает данные/авторизацию
xcrun simctl launch $UDID <bundle-id>          # печатает pid
xcrun simctl openurl $UDID "scheme://path"
xcrun simctl io $UDID screenshot /tmp/shot.png
xcrun simctl terminate $UDID <bundle-id>

# Метрики процесса (петля/утечка видна по росту RSS)
PID=$(pgrep -f <AppName>.app | head -1)
ps -o rss= -p $PID; sleep 3; ps -o rss= -p $PID
```

## Нюансы и грабли

- **Предусловие сессии — авторизация**: залогинить приложение без тапов
  агент не может. Использовать симулятор, где пользователь уже авторизован
  (обычно его рабочий booted-симулятор); `simctl install` поверх сохраняет
  данные. Если авторизованного нет — попросить пользователя залогиниться
  один раз руками.
- **Клавиатуру без тапов не поднять снаружи** — фокус делать из кода:
  в лаб-экране `becomeFirstResponder()` в `viewDidAppear` /
  `@FocusState = true` в `onAppear`, параметр «фокусировать поле» — сегментом
  диплинки. Учитывать, что при подключённой hardware-клавиатуре Mac
  экранная может не показаться (Simulator → I/O → Keyboard → Connect
  Hardware Keyboard выключить руками — попросить пользователя).
- Замёрзшее приложение убивать сразу после снятия артефактов: петля с
  ростом RSS выедает память хоста (гигабайты в минуту).
- Скриншот при фризе показывает последний ОТРИСОВАННЫЙ кадр — см. граблю в
  [temp-deeplink](temp-deeplink.md).
- Тапы: `simctl` их не умеет; AppleScript по окну Simulator хрупок (окна
  часто не скриптуются). Не закладываться на тапы вовсе — конфигурация
  через диплинку.

## Вариации

- **Флаки-протокол**: для нестабильных багов — серия одинаковых прогонов с
  перезапуском приложения между ними; фиксировать частоту («3 из 10»), а
  «не воспроизводится» писать только с числом прогонов. Сколько прогонов
  достаточно — от частоты в проде; по умолчанию ≥5 до вывода.
- **Наблюдение в цикле**: `Monitor`/фоновый `until`-цикл по маркеру в
  лог-файле проб — заметить событие, не опрашивая руками.
