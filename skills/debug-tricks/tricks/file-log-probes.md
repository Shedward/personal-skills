# file-log-probes — лог-пробы, пишущие в файл

## Когда

- Нужно видеть рантайм-поведение: какая ветка исполнилась, с какой частотой
  дёргается метод, есть ли петля.
- **Главный тред может встать** (фриз, петля): консоль/дебаггер недоступны, а
  файл продолжает писаться с фоновой очереди — лог переживает фриз.
- Агент водит приложение сам и читает лог между действиями (`tail`, `grep`)
  или в цикле.

## Как

1. Мини-хелпер в каждом инструментируемом модуле (internal, копипаста на
   ~25 строк — это нормально для временного кода): `FileHandle` append на
   собственной serial `DispatchQueue`, timestamp `HH:mm:ss.SSS`, префикс
   модуля в строке (`[DS]`, `[Module]`).
2. Путь — `/tmp/<probe-name>.log`: **симулятор пишет прямо в /tmp хоста**,
   никакого sandbox-контейнера искать не надо.
3. Пробы ставить во ВСЕ узлы причинной цепочки разом (вход/выход, гварды,
   ветки rebuild/in-place), а не по одной: одна сборка — полная картина.
4. Высокочастотные точки — троттлить счётчиком: логировать первые ~20
   вызовов + каждый 200-й, номер вызова в строке. Петля в 1000 р/с даст
   читаемые ~5 строк/с, а по номерам видна точная частота.
5. В строку пробы класть **состояние мира**, по которому будут различаться
   гипотезы: `win=\(window != nil)`, `raw=\(size)`, `subviews=\(n)` — одна
   строка лога хоронит целую гипотезу (например, «гонка монтажа»).
6. Протокол прогона: очистить файл → маркер прогона из хоста
   (`echo "=== RUN N: <конфиг> ===" >> /tmp/….log`) → действие → снять
   копию лога как артефакт (`cp` в папку лабы) → `xcrun simctl terminate
   <UDID> <bundle-id>` (остальная механика — в
   [simulator-driving](simulator-driving.md)).

## Нюансы и грабли

- Два модуля с двумя `FileHandle` на один файл = изредка перемешанные/битые
  строки. Терпимо для глаз; если критично — разные файлы на модуль.
- Очередь — `async`: при OOM-kill хвост может потеряться. Снимать копию
  лога ДО того, как процесс убьют, а не после.
- Пробы = временный код. Единый префикс имени (`navlab`, `probe`) — снятие
  перед PR одним грепом: `grep -rn "<префикс>" …`. Проверять `git diff`, что
  после снятия остался только фикс.
- На физическом девайсе `/tmp` хоста недоступен — трюк симуляторный. Для
  девайса — писать в Documents и вынимать `simctl`-аналогами/`devicectl`.
- `NSLog`/`os_log` + `log stream` — альтернатива без правки файлов, но:
  сбор надо запускать заранее, поток шумный, при фризе буферы могут не
  доехать. Файл проще и надёжнее.
- Метрики процесса снимать параллельно с логом: `ps -o rss= -p <pid>` в
  цикле — рост RSS подтверждает петлю даже при молчащем логе.
- Сигнатура хелпера — plain `String`, не `@autoclosure @escaping`: в
  автоклоужере обращения к свойствам `self` требуют явного `self.` и
  сборка падает на каждой пробе (`implicit use of 'self' in closure`).
  Строка формируется на месте вызова — цена копеечная, ошибок нет
  (15.09.2026, MOB-64488).
- Сессия в fish-шелле: `grep --include=*.swift` без кавычек падает на
  глобе («no matches found») — писать `--include='*.swift'` или фильтровать
  через `| grep swift`; `echo ===X` тоже ломается — ставить в кавычки.
- Пробу «кто вызвал» делать параметром `caller: String = #function` у
  инструментируемого метода: дефолт `#function` вычисляется на стороне
  вызывающего — все call-site'ы подписываются сами, без правок в них.

## Вариации

- **Проба «до/после перехода»**: в `didShow`/`viewDidAppear` замерить
  финальное состояние (`convert`-фрейм) и сравнить с закешированным
  (`MISMATCH=`); плюс тот же замер через `DispatchQueue.main.async` — ловит
  дозаход лэйаута после делегата. Одна строка `MISMATCH=true` хоронит
  версию «после перехода ничего не меняется».

- **Проба-счётчик частоты**: копить вызовы и печатать «N запросов/с» раз в
  секунду — когда важна только частота (вариант для standalone-репро без
  чтения файла: `print` в консоль).
- **Проба-диф**: логировать только смену значения (гвард `!= old`) — для
  осцилляций фреймов/стейта.
- **Проба «кто анимирует — SwiftUI или UIKit»** (MOB-65525): на спорную
  SwiftUI-вью повесить `.transaction { navprobe("animation=\(String(describing: $0.animation)) …") }`,
  а в UIKit-точке обновления хоста логировать `UIView.inheritedAnimationDuration`.
  `animation=Optional(AnyAnimator(SwiftUI.DefaultAnimation()))` при
  `uikitAnimDuration=0.0` = протечка чужого `withAnimation {}` без явной
  анимации (`.default`); именованный изинг залогируется своим типом.
- **Пробы живут в отдельном стэше** (`git stash push -u -m "navprobe: …"`)
  и возвращаются `stash apply` (не pop) на любую ветку, где те же файлы:
  переключение задач не теряет пробы, а снять их перед PR — `grep -rn
  navprobe` + удалить helper. Классификатор auto-mode блокирует `stash
  apply` агенту — пользователь делает `! git stash apply stash@{N}`.
- **Проба в completion с захваченным индексом**: логировать и захваченное,
  и фактическое (`didSelect \(index) actual=\(selectedPageIndex)`) —
  одна строка `didSelect 0 actual=Optional(1)` доказывает гонку
  «устаревший completion перебивает актуальный выбор» и синхронность
  обновления `viewControllers` при `animated: true`.
- **Baseline-артефакт**: лог прогона «до фикса» сохранить в лабу
  (`~/.claude/docs/<project>/labs/<задача>/`) с README про условия — после
  фикса сравнивать те же точки.
